## 1. Purpose and authority boundary

This contract refines only the public Desktop presentation of the already
implemented Locus V2 surface. It does not rewrite the hash-frozen G9U0 spec,
prompt, report or evidence. Where the historical design row or frozen spec
mentions candidate markers, the implemented G9U0 authority is the opaque exact
token and explicit inspector materialization; graphical marker presentation is
prospective G9U1 scope.

No menu, dialog, token helper or future marker is geometric or identity
authority.

## 2. Product menu lifecycle

The GeoCeDG product menu has one population authority. It must be populated
after initial and repeated full menubar initialization, one or repeated font
updates, localization/language refresh and normal menubar update/rebuild.

The existing independent DXF action remains governed by its current policy.
With `--enableLocusV2=true`, and without any second intersection flag, the menu
exposes the approved Locus V2 creation, semantic-point, total-length,
partial-length and rich-result inspector actions. With the feature off, those
creation/inspection actions follow the approved unavailable policy while
supported persisted objects remain loadable/preservable.

## 3. Inspector and exact-token materialization

The real menu action must reach the existing controller/dialog route for an
Algebra-selected rich result, the sole unselected rich result or a deterministic
choice among several results. Metric rich results and typed no-result feedback
remain supported.

An admissible-solution chooser presents a localized compact label containing a
transient solution ordinal and contact classification. That ordinal exists only
inside the current inspector snapshot. Neither it nor list order is token
identity, persistence authority, continuation identity or command input. The
complete opaque token remains unchanged and is the only value passed to exact
point materialization. It must not be used as a combo-box label or otherwise
determine the preferred width of an interactive control or dialog.

The read-only diagnostic area may expose the complete token, but must wrap or
scroll within a bounded normal-Desktop viewport. The chooser retains its
accessible name and keyboard selection; ordinary keyboard OK/Cancel must remain
visible and usable without horizontal off-screen navigation.

`Intersect(L,T)` publishes the rich result and zero persistent point children.
Cancel creates zero points and zero token children. Explicit acceptance of one
currently admissible exact token creates exactly one ordinary point whose normal
DAG inputs are the rich result and opaque token. The point never re-solves and
never establishes identity from coordinate, order, index or proximity.

## 4. Auxiliary token presentation

When existing persistence represents the token through an auxiliary `GeoText`,
that exact helper remains a normal reconstructible, persistable, copy/remappable
dependency. It is not ordinary Euclidian presentation and must not display its
opaque string in Graphics. Its content, durable lifecycle, XML and token-ledger
semantics remain unchanged. Save/reopen, copy and ordinary undo/redo preserve
the approved dependency.

## 5. Exclusions and future G9U1 boundary

R3 introduces no candidate-marker overlay, drawable rich result, automatic
persistent point, new feature flag, kernel/solver change, semantic revision,
identity/token migration, XML change, render change, generic `Path` or workspace
implementation.

Future G9U1 may add transient markers for the active/selected rich result. Such
markers are presentation overlays only: no GeoElement, durable ID, XML,
Construction Protocol entry, DAG node, undo object, semantic revision or token
identity. They may rank or preselect already admissible exact tokens but never
establish identity.

## 6. Validation and exit

R3-M01–M06, R3-I01–I11, R3-T01–T03 and R3-N01–N02, two deterministic focused
runs, historical G9U0/R1/R2/G9X1/G5/G9A/legacy gates, Checkstyle, Git diff and
composed verification pass. The initial author smoke confirmed the functional
workflow while exposing the long-token width defect; the bounded correction,
replacement automation and author re-smoke pass. This author-approved R3 closeout
does not authorize G9U1.
