# GeoCeDG 1.2.0 — bounded native MEMORY repair (R9)

Classification: implementation/debugging, shared kernel trusted-memory restoration.
Authority: current NativeTransactionalState2D, CU7 R3/R4 restoration and work-budget contracts, the adopted CU7 R5 D1 clause 8 separating MEMORY and FILE, and the author-authorized 1.2.0 D1 Route S. The final Desktop cone placement exposed a legitimate UNSUPPORTED_SOURCE_CLOSURE at B = Point(OrthogonalLine(A,xAxis)); earlier query-only evidence did not exercise publication.

## Defining perimeter

No geometric admission or inverse search is added. The existing Route S query/choice/publication, semantic address, one-use freshness guards and normal construction DAG remain authoritative. MEMORY additionally recognizes exact native AlgoOrthoLinePointLine, AlgoLinePointLine, AlgoUnitVectorLine, AlgoIntersectLines, and GeoAngle values with positively supported transitive inputs. The FILE algorithm/value/operation tables and ordinary public serialization remain unchanged. Raw angular literals, signed-zero loss, unknown procedures, macros, regions, unsupported native places and work-budget exhaustion keep their existing exclusions.

The reusable line/conic selector class is exact AlgoIntersectLineConic on a full GeoLine and full regular GeoConic, with two finite distinct outputs and a settled two-root permutation. Tangent-provider, limited-path, incidence-special-case, pending/initial, degenerate and subclass states remain unsupported. The primitive is not selected by document name or coordinates. Native line/line intersection has no retained branch selector and continues through its ordinary deterministic cross-product computation. Named GeoAngle inputs retain their native raw angle/style through normal XML; angular expression literals gain no permission.

## Immutable selector payload and lifecycle

The line/conic algorithm owns a version-1 immutable MEMORY payload. It captures exact raw/inhomogeneous P, Q and D coordinates, permutation, ages, alive/on-path flags, first/permutation-pending flags, and inherited loaded-output flags. Input line/conic NativePathState2D snapshots guard its defining geometry and domain. Temporary distance/list work is overwritten before it is read by a new selection and is not geometric state; no mutable GeoPoint, algorithm or construction reference is retained by the payload.

The MEMORY source pass records only positively witnessed selector producers used by supported free-place closures. Capture reuses that bounded pass, without a second uncharged traversal. Each selector is associated through the existing nativeRollbackBinding on its typed first output P[0], or that output's already existing durable ID. This is a snapshot-owned reconstruction correspondence, not label/order/proximity identity and not a new public ID. The resolved output must belong to the exact producer class and the fixed output role.

The algorithm installs a pending payload only under the active owning Construction restore session. Its normal compute applies that payload while loading and consumes it exactly once in the first normal post-load DAG computation, after exact source-state validation. No extra DAG, proximity remapping or repeated search is run. Missing/foreign/replayed bindings and changed inputs fail closed. finishRestore checks the payload, every existing native-place input, registry/reservations and unchanged ordinary XML. UndoTemplate freezes immutable data and digest only; every Undo/Redo creates a fresh one-use restore session. Ordinary reopen uses the unchanged public format and must independently preserve the published semantic point and normal native output correspondence.

R9 diagnostic refinement, before its corrective code: a downstream native
place such as Point(Line(J,K)) can be reconstructed by the normal XML reader
before the final update DAG. Once the selector's exact P[0] role is bound and
the current line/conic NativePathState snapshots match, installation therefore
also applies the immutable selector data immediately. This restores archived
inputs for that normal downstream construction; it does not compute another
DAG or search for a root. The payload remains pending and the normal compute
reapplies it after XML coordinates are read, consuming it exactly once in the
first post-load DAG. If the source states do not yet match at installation,
no selector geometry is changed; the pending payload retains its existing
source checks and fails closed if they do not hold at the required boundary.
Authentication, cardinality, private binding, output role and negative tests
remain unchanged.

R9 exact-source deferral, designed after memorydiagnostic01 and before code:
all six remaining Shared failures report an authenticated native point with
the correct parent/path and exactly one differing source bit slot. The line's
z coefficient is -0.0 in the captured source and +0.0 during its XML element
read. The normal XML numeric attribute canonicalizes zero, while the line's
unchanged construction recomputes -0.0 in the ordinary post-load DAG. This
is a transient representation difference, not permission to equate the two
binary states.

A correctly authenticated native-point payload may therefore remain pending
while kernel loading is active and its current source does not yet match.
It is not applied in that state. Its ordinary producer compute also leaves
the payload pending when a loading-time source mismatch persists, allowing
the normal reader/DAG lifecycle to finish. The first post-load producer
compute must find the original exact source state, apply the payload and
consume it exactly once; otherwise it throws. Unauthorized installation is
always rejected immediately. No source comparison, tolerance, FILE codec,
XML number, source geometry or DAG invocation is changed. finishRestore
still requires consumption and exact source/input/registry/XML restoration.
The focused regression asserts the original line.z negative-zero bits,
retained bits after rollback, one normal DAG and no surviving point payload.
Existing changed-source/foreign/duplicate/rebound tests remain mandatory.

R9 reconstruction-context refinement, designed from Desktop05 before code:
the actual cone's failed-publication rollback enters processConstructionSnapshot
because its snapshot contains Control Layout. That lower-level reader sets
Kernel loading mode but does not set Construction fileLoading. Without the
reconstruction context, historical LocusLength commands become new public
numeric objects, and their historical Length consumers reject those numbers;
subsequent identity/binding errors are parse-failure consequences. Normal
Construction.processXML and the higher-level XML reader already scope this
context explicitly.

The rollback boundary must save the prior fileLoading flag, set it true while
reading/restoring its local snapshot, and restore it in finally on either
success or failure. It retains the same Control Layout route, CAS context,
load purpose, private payloads, exact checks and single normal update DAG.
Shared oracles include a real Control Layout panel/slot, historical rich
LocusLength plus Length consumer and a new numeric LocusLength. Both false
and true entry flags must survive successful mutation, successful rollback,
and an injected reader failure. A reader failure remains a catastrophic
restoration failure; the test does not treat a partially restored host as
success. The immutable cone's adversarial publication test remains the real
Desktop integration oracle.
