The author, not the agent, decides whether a compensating rollback with a

## 1. Question

`F3R-ATOMICITY-COMMIT`: a failure during or after the real commit, after
admission and a passing dry run, of an insertion that the inherited paste has
already started. Serializable restoration is not runtime atomicity.

## 3. Options

### K1 — restricted compensating rollback (refined, two paths)

```text
PATH K1-S (subtractive, no rebuild)
  WHEN    the paste returned normally, no created object participates in the identity
          registry (so the paste stored no undo state), and the failure is detected
          afterwards (strict verification, degradation, later stage fault)
  DO      remove the created objects in reverse construction order; remove macros
          transferred by this operation; restore the saved flag; report "not inserted"
  KEEPS   live instances, F2 memory, IsoABorder link (expected, not separately
          probed), layers, undo history, clipboard and provenance
  LOSES   selection (already cleared by the inherited paste); the document root UUID
          regenerated by the paste route

PATH K1-R (rebuild with declared session reset)
  WHEN    the paste itself failed (exception inside the inherited atomic evaluation,
          which already rebuilt), or created objects participate in the identity
          registry (the paste stored a full undo state)
  DO      if the paste stored: wait for that store, then undo() and pruneStateList();
          if it did not: nothing more (the inherited rollback already restored);
          remove transferred macros; restore the saved flag; report "not inserted;
          the drawing was reloaded from its state before the insertion"
  KEEPS   construction XML, durable ids, dependencies, units, layers of drawable
          objects, hidden set, working layer, undo history, clipboard and provenance
  LOSES   live instances, F2 memory, IsoABorder export link, selection; non-drawable
          numbers and lists are re-layered to the highest used layer (not serialized)

SERIOUS FAILURE
  WHEN    the inherited rollback throws, the awaited store does not arrive, or any
          post-recovery certificate check fails
  DO      no further automatic mutation; a distinct error ("the drawing could not be
          verified after a failed insertion; save under a new name or reopen"); the
          document is marked modified; never reported as an ordinary rejection
```

### K2 — stronger, non-rebuilding transaction

Guarantees K1 cannot give: runtime atomicity (no rebuild) for identity-bearing
payloads and for failures inside the inherited atomic evaluation. Required
changes:

| Boundary | Change | Layer | Impact |
|---|---|---|---|
| `InternalClipboard.restoreClipboardSnapshot` / `evalClipboardXMLAtomically` | subtractive rollback of the created elements and their identity records instead of a clearing reload | shared (`source/shared/common`) | every paste in GeoCeDG, Classic and web; the G9A identity rollback protocol (`ROLLBACK_RESTORE`); spatial registry retirement semantics |
| `CopyPasteD.pasteFromXML` / `UndoManager.storeAddGeo` | defer or suppress the paste's own undo store until the orchestration commits | inherited Desktop and shared | undo semantics of every identity-bearing paste |
| optional synchronous store API in `UndoManagerD` | observable store failure | inherited Desktop | all undo stores |

Consequences: shared clipboard and undo semantics change for every frontend; a
new rollback algorithm in the identity protocol; existing G9A/G9U and D1 tests
affected; Classic behavior changes. Under `verification-levels.md` §12.8 a
change of a shared contract consumed by every paste route is a global-impact
fact: an author reclassification review is required (likely `GLOBAL_IMPACT`,
`FINAL`). Remaining uncertainty: whether identity retirement on subtractive
rollback reproduces the pre-paste registry exactly (not probed).

### S — strict fallback

S rejects before mutation; it cannot remove commit-time failures, which are not
content-determined. It can coexist with K1 **per payload class** without
weakening the contract: for example, if the author rejects K1-R's session reset,
identity-bearing payloads (Locus V2 family, Spline V2) would be rejected
before mutation (S) and only K1-S payloads admitted. That conflicts with the
author's priority for specialized objects. S never silently replaces K1: every
payload class has exactly one declared recovery path.

## 5. Recommendation (agent proposal; author disposition pending)

**K1 refined (K1-S + K1-R + serious-failure path)**, with S used only where the
author excludes a payload class. Rationale: it is U0; it gives full runtime
atomicity for payloads without identity records when the failure is detected
after the paste returns (the common detected case: degradation, verification);
it restores the complete serializable document in every other case; Q1 shows
that the earlier procedure must not be used and Q2 provides the safe ordering.
Assumptions: failures inside the inherited atomic evaluation are environmental
or resource failures after a passing dry run; the author accepts the declared
session reset for K1-R.

### Proposed normative wording

> An insertion is accepted only when admission, the dry run, the commit and the
> strict verification all succeed; it is then one undo step. Any failure before
> the commit leaves the document and the session unchanged. A failure detected
> after a commit that created no identity-bearing object is compensated by
> removing exactly the created objects; the document, its objects, the undo
> history and the session are as before, except that the selection is cleared
> and the Move tool is active. Any other commit-time failure restores the
> drawing from its last undo state after the insertion's own undo state has been
> taken back; the construction, durable identities, units, layers and undo
> history are as before; live object instances, the remembered references of
> Parallel/Perpendicular, the IsoABorder export link and the selection are
> reset as after an Undo, and the user is told so. Transferred macros are
> removed and the saved state is restored in every case. If the restoration
> itself fails, or its result cannot be verified, GeoCeDG reports a distinct
> serious error, performs no further automatic change and marks the document
> modified; it never reports such a case as an ordinary rejection.

### Mandatory implementation gates

1. The orchestration knows deterministically whether the paste stored an undo
   state (completed paste and any created object participating), and waits for
   that store before compensating; a missing store is a serious failure.
2. K1-R uses `undo()` + `pruneStateList()` after the store, never an immediate
   `restoreCurrentUndoInfo()`; a regression test reproduces `DQ21-Q1` and proves
   no reappearance.
3. K1-S removes exactly the created objects; tests prove instance continuity,
   F2 memory and IsoABorder link preservation and an unchanged undo history.
4. Saved flag and macro list restored in both paths; nested macros included.
5. The serious-failure path is reachable by an injected recovery fault and never
   produces a success or ordinary-rejection message.
6. Every path is covered by the serializable **and** runtime certificate.

### Residual risks

- K1-R session reset (instances, F2 memory, IsoABorder link, selection) when
  it applies.
- Root document UUID regenerated by the paste route in K1-S (not geometric).
- Recovery failure leaves an uncertified document (reported, not hidden).
- The inherited paste always clears the selection and activates Move.

### Classification consequence

K1 (any path) and S: GeoCeDG Desktop only — `INTEGRATED_PHASE` stays
appropriate. K2: shared rollback and undo changes — author reclassification
review, likely `GLOBAL_IMPACT`.
